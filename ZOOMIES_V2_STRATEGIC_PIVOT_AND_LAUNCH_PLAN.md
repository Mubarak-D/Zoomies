# ZOOMIES — STRATEGIC PIVOT & ASAP LAUNCH PLAN
## V2 Addendum to the Master Website Blueprint

> **New information locked in:**
>
> - Zoomies currently has only Instagram as its active public channel.
> - Launch needs to happen ASAP.
> - The mission is to get more people into running.
> - Zoomies is NOT a generic weekly running club.
> - Runs can include activities, games, challenges, social experiences, and unexpected formats.
> - The culture must make people feel they can join without overthinking.
> - Everyone should feel welcome, seen, and acknowledged.

---

# 1. THIS CHANGES THE PRODUCT DEFINITION

The original plan positioned Zoomies primarily as:

> A social running community.

That is incomplete.

## Revised definition

> **Zoomies is a community that uses running as an excuse to get people moving, playing, meeting, exploring and showing up.**

The distinction matters enormously.

A traditional run club asks:

> "Do you want to come running?"

Zoomies should ask:

> **"Want to come do something fun? Oh, and we're running too."**

That positioning opens the door to people who currently think:

- "I'm not a runner."
- "I'm too slow."
- "Run clubs sound intimidating."
- "I don't want to just run in a straight line for 5 kilometres."
- "I don't know anyone there."
- "I don't know if I'll fit in."

Zoomies needs to make the act of joining feel lower-risk than the act of staying home.

# 2. THE CORE BRAND TRUTH

## Do not sell running first.

Sell:

### EXPERIENCE.

Then:

### PEOPLE.

Then:

### MOVEMENT.

Running is the medium connecting all three.

The hierarchy becomes:

```text
FUN
↓
BELONGING
↓
MOVEMENT
↓
RUNNING
```

Not:

```text
RUNNING
↓
RUNNING
↓
MORE RUNNING
```

This is the strongest strategic distinction available to Zoomies.

# 4. THE ZOOMIES PROMISE

Every event should satisfy at least one of these:

### MOVE
Physical activity.

### PLAY
A challenge, game, mission, competition or twist.

### CONNECT
People actually interact.

### DISCOVER
A new place, route, idea or experience.

### REMEMBER
There is something worth talking about afterwards.

This can become the internal event filter.

Before approving an event:

> Does it have at least 2 of these?

If an event is just:

```text
Meet
Run
Leave
```

then it is probably not Zoomies enough.

---

# 5. THE REAL COMPETITIVE GAP

Traditional run clubs generally organise around:

- recurring schedules
- pace groups
- distances
- training
- consistency

Zoomies should organise around:

- experiences
- themes
- surprises
- participation
- social energy
- accessibility

That does NOT mean abandoning proper running structure.

Safety, route clarity and pace management still matter.

But they are infrastructure.

They are not the headline.

The Zoomies differentiation should be:

> **You don't know exactly what every event will feel like, but you know it won't be boring.**

---

# 6. THE BIGGEST UX PRINCIPLE: REMOVE THE SECOND THOUGHT

The team explicitly wants people to:

> Not think twice. Just join.

That should become a UX doctrine.

## Every friction point must be questioned.

Ask:

### Does the user need an account?

No.

### Do they need to understand the whole organisation?

No.

### Do they need to know people?

No.

### Do they need to be experienced?

No.

### Do they need special equipment?

Preferably no, unless clearly event-specific.

### Do they need to fill a long form?

No.

### Do they need to figure out what will happen?

No.

The website should constantly communicate:

# SHOW UP. YOU'RE GOOD.

Not literally everywhere, but emotionally.

---

# 7. INCLUSION CANNOT BE A SENTENCE

The old approach would have had a section saying:

> Everyone is welcome.

That is insufficient.

Inclusion must be designed into the system.

## How a first-timer experiences Zoomies

### Before joining

They see:

```text
FIRST TIME?
COME ANYWAY.
```

### On event page

They see:

```text
COMING SOLO? MOST PEOPLE DO.
```

### Pace information

They understand:

```text
NO ONE IS EXPECTED TO KEEP UP WITH THE FASTEST PERSON.
```

### During registration

A question:

```text
IS THIS YOUR FIRST ZOOMIES?
YES / NO
```

Not for exclusion.

For acknowledgement.

### After RSVP

They receive:

> First time? We'll make sure you know where to go.

### At event

A designated welcome moment.

### After event

The team acknowledges participation.

That is how "everyone is welcome" becomes operational rather than marketing copy.

# 8. THE ACKNOWLEDGEMENT SYSTEM

The user specifically mentioned that everyone should be acknowledged.

This is interesting and should become a real product principle.

Call it internally:

# THE ZOOMIES "NO INVISIBLE PERSON" RULE

Every person should feel that they arrived somewhere that noticed them.

This doesn't require technology.

## Event-level system

### First timers

Organiser knows who is new.

### Arrival

Someone says hello.

### During activity

Nobody is silently excluded.

### Finish

Everyone is acknowledged.

### Social content

### Community

Avoid cliques becoming the visual identity.

# 9. EVENT DESIGN SYSTEM

Zoomies should not have one event format.

Create a modular event taxonomy.

## TYPE 01 — CLASSIC

A straightforward social run.

Purpose:

- consistency
- habit building
- community maintenance

Example:

```text
SUNDAY EASY
5KM
SOCIAL PACE
```

---

## TYPE 02 — CHALLENGE RUN

The route contains a mission.

Examples:

- checkpoint scavenger hunt
- collect stamps
- solve clues
- complete mini challenges
- team objectives

The important part:

The activity must not compromise road safety.

---

## TYPE 03 — THEMED RUN

A concept changes the experience.

Examples:

- colour theme
- decade theme
- costume-lite
- sunset run
- music theme
- city theme

Do not make themes mandatory if they create embarrassment.

Participation should be easy.

---

## TYPE 04 — SOCIAL GAME RUN

Teams.

Games.

Interaction.

Examples:

```text
RUN → CHECKPOINT → TASK → RUN
```

This could be one of Zoomies' strongest formats.

---

## TYPE 05 — DISCOVERY RUN

The run exists to explore.

Examples:

- hidden Colombo
- food stops
- architecture
- coastal routes
- neighbourhood exploration

---

## TYPE 06 — COLLAB RUN

Partner with:

- cafés
- creative communities
- sports brands
- photographers
- artists
- wellness communities

The partner should add something experiential.

Avoid random sponsor logo dumping.

---

## TYPE 07 — SPECIAL EVENT

Rare.

Higher production.

Examples:

- anniversary
- night event
- large challenge
- charity event
- city-wide game

These become major content moments.

---

# 10. THE EVENT GENERATOR FRAMEWORK

Before creating any Zoomies event, answer:

## THE FIVE QUESTIONS

### 1. What makes this different?

If answer:

> "The route is nice."

Not enough.

### 2. What will strangers interact about?

Design social interaction deliberately.

### 3. What is the moment people will remember?

There needs to be at least one.

### 4. Can a beginner participate?

If not, clearly label it.

### 5. What will make someone post it?

Not every event must be Instagram bait, but memorable experiences naturally generate content.
